- **Thay đổi gì / ở đâu:**
  - `api/openapi.yaml`: `CoverageArea` (dùng trong `GET /api/v1/app/config`) thêm `bbox` và `graphVersion`; thêm `security: []` + `license.identifier` để Redocly lint pass (không đổi endpoint/schema).

- **Làm gì:** Chốt **không mở `GET /api/v1/coverage` ở v0**. `GET /api/v1/app/config` trả `coverage.areas[]` gồm `id`, `code`, `name`, `bbox` (`[minLon, minLat, maxLon, maxLat]`), `modes`, `dataStatus`, `graphVersion`. `bbox` chỉ để client chặn nhanh điểm hiển nhiên ngoài vùng; server vẫn quyết định cuối bằng `ST_Intersects` trên polygon thật. `/routes/plan` vẫn trả `UNSUPPORTED` với `details.reason=OUTSIDE_COVERAGE`.
- **Vì sao:** Client cần báo sớm “ngoài vùng hỗ trợ” ở màn Unsupported mà không phải gọi route trước. Vùng phủ là thông tin công khai, không PII. Chưa cần polygon đầy đủ ở v0; thêm endpoint riêng khi app cần vẽ ranh giới lên bản đồ, lúc đó mới cân nhắc `ETag`.
- **Bằng chứng / kiểm thử:**
  - Parse `api/openapi.yaml` bằng Ruby: OpenAPI `3.1.0`, 13 path, 51 schema, **0 `$ref` thiếu**, 13 `operationId` không trùng.
  - `npx @redocly/cli@2.80.0 lint api/openapi.yaml`: **valid**, 3 warnings (localhost server, health không có 4XX).
  - Kiểm link tương đối trong 3 file tài liệu: **0 hỏng**.
  - `git diff --check`: sạch.
  - **Chưa kiểm chứng:** chưa có code/DB nên chưa kiểm `ST_XMin/ST_YMin/ST_XMax/ST_YMax` trên dữ liệu thật; bbox TP.HCM trong ví dụ là `DEMO`.
- **Ảnh hưởng / rủi ro:** `api/openapi.yaml` vẫn đang `Proposed`; bbox ví dụ chưa phải biên giới chính thức. Client không được dùng bbox để kết luận “trong vùng” — chỉ để loại nhanh điểm ngoài.
- **Việc tiếp theo:** Chủ dự án duyệt/merge; khi làm app/config thật, tính bbox từ `coverage_area.area` và `graphVersion` từ graph build `ready`; mở `GET /coverage` + `ETag` khi cần vẽ polygon.
